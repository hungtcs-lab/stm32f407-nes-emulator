# 硬件资料

原理图和数据手册在同一目录：`STM32_F4VE--核心板原理图.PDF`、`TFT3.2吋液晶-原理图.pdf`、`STM32F407VET6数据手册.pdf`。

## 核心板

- MCU：STM32F407VET6，Cortex-M4F，Flash 512KB，SRAM 192KB（SRAM1 112K + SRAM2 16K 连续于 0x20000000，另有 CCM 64K 于 0x10000000）
- 晶振：HSE 8MHz（Y2），LSE 32.768kHz（Y1）
- 时钟配置：HSE → PLL（M=8, N=336, P=2, Q=7）→ SYSCLK 168MHz，AHB 168MHz，APB1 42MHz，APB2 84MHz，USB/SDIO 48MHz
- Flash 168MHz 需 5 个等待周期，ART（预取 + 指令/数据缓存）必须打开

## 引脚分配

### SD 卡（SDIO 4 线）

| 信号 | 引脚 | 板上 |
|---|---|---|
| D0 / D1 / D2 / D3 | PC8 / PC9 / PC10 / PC11 | 各 10K 上拉 |
| CK | PC12 | 10K 上拉 |
| CMD | PD2 | 10K 上拉 |

- 没有卡检测信号，只能靠初始化超时判断有没有卡
- 卡座电源只有一个 100nF 去耦，建议补 10～47µF

### LCD（FSMC，16 位并口）

| 信号 | 引脚 |
|---|---|
| D0~D15 | PD14 PD15 PD0 PD1 PE7~PE15 PD8 PD9 PD10 |
| RD (NOE) | PD4 |
| WR (NWE) | PD5 |
| CS | **FSMC_NE1**（PD7） |
| RS | **FSMC_A18**（PD13） |
| 复位 | 接板子 RST，没有单独 GPIO |
| 背光 | **PB1，高电平点亮**（核心板 Q2 + 屏上 Q1 两级 PNP） |

- **VET6 版用 NE1 + A18，ZET6 版用 NE4 + A6**，网上的 ZET6 代码地址不能直接用
- 地址：命令 `0x60000000`，数据 `0x60080000`（16 位总线下 FSMC_A18 对应 HADDR19）
- 控制器：ILI9341（读 0xD3 得到 `00 00 93 41`）
- 横屏方向：`MADCTL = 0xA8`
- FSMC 写时序：ADDSET=2、DATAST=3（逐像素读回校验：DATAST=1 会错像素，DATAST≥2 无错）
- 屏的 FMARK（撕裂同步）没有引出，无法和面板刷新同步
- 实测：全屏 320×240 填充约 3.4ms；推一帧 NES 画面（256×240）约 3.5ms，瓶颈在 CPU 不在总线

## 调试接口

- 20 针 ARM JTAG 座：1=Vref(3V3)，7=TMS/SWDIO(PA13)，9=TCK/SWCLK(PA14)，15=nRST，偶数脚 4~20 为 GND
- PA13 上拉 10K（R2），**PA14 下拉 10K（R9）**，所以 pin 9 测出来 0V 是正常的
- SWD 只接 SWDIO / SWCLK / GND 三根，板子独立供电时**不要再接调试器的 3.3V**
- BOOT0 跳线：0 = 从 Flash 启动（正常），1 = 进 ST 出厂 bootloader（**烧完程序记得改回 0，否则程序不运行**）
- ST-Link V2 克隆棒（固件 V2J21S4）：st-flash 可用；probe-rs 要求固件 ≥ V2J26，不认

### 自制 DAPLink（STM32F103C8T6，DAP103 固件）连不上这块板

- 同一个 DAPLink、同样的 3 根线，连 STM32F103RC 板正常，连这块 F407 板无应答（`No target responded to the debug port`）
- ST-Link 用同样接线能正常连 F407
- 最可能的原因：这块板 SWCLK（PA14）上有 R9 10K 下拉，DAPLink 的时钟输出驱动能力不够或引脚配置不对
- 探头侧：PB13 = SWCLK，PB14 = SWDIO

## 内存和 Flash 布局（NES 固件）

| 区域 | 地址 | 大小 | 内容 |
|---|---|---|---|
| Flash 扇区 0~5 | 0x08000000 | 256K | 程序（约 170K） |
| Flash 扇区 6~7 | 0x08040000 | 256K | ROM 存储区：128 字节头 + .nes 原文件 |
| SRAM | 0x20000000 | 128K | 程序数据、44K ROM 缓冲、栈 12K（约用 105K） |
| CCM | 0x10000000 | 64K | InfoNES 的 RAM / SRAM / PPURAM / ChrBuf，正好占满 |

- CCM 只挂在 D 总线：**DMA 访问不到，也不能执行代码**
- 只有 SRAM1（112K）能重映射到 0 地址，访问 SRAM2 的别名会 BusFault
- 代码放 Flash 执行最快：放 SRAM 执行慢 40%，SRAM 重映射到 0 地址执行慢 8%

## SD 卡

- 12MHz（`SD_CLOCK_DIV=2`）轮询模式稳定：读 3.4MB/s，写 2.0MB/s
- 24MHz 轮询不稳定（多块写超时），要换 DMA
- 4.8MHz 以下 CPU 半速时出现过 TX_UNDERRUN，全速后没有
- 冷启动时卡对第一条 CMD55 可能不应答，需要重试
- 遇到过接触不良：应答全是 CRC 错误，重新插卡解决
