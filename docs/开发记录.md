## InfoNES 核心改动（摘要）

详细见 `lib/infones/PORTING.md`。

- 整帧缓冲 120KB → 单行缓冲，每行画完调 `InfoNES_LoadLine()` 直接推屏
- `RAM/SRAM/PPURAM/ChrBuf` 放 CCM；APU 事件队列 15000 → 512 并加越界检查
- 去掉带大数组的 Mapper 5/6/19/85/188/235
- 类型改成固定宽度（原 `DWORD=unsigned long`，64 位主机上出错）
- 修上游越界：关屏时精灵合成倒推指针越界
- 像素改 RGB565，背景标记放 bit5
- 精灵合成优化：精灵缓冲延迟清零，只扫有精灵的范围
- 新增 `InfoNES_ShouldDrawLine()` 钩子，平台层实现隔行渲染
- 行缓冲改成两块 + 指针 `WorkLine`，平台层推屏时轮换（DMA 发一块、核心画另一块，免拷贝）
- `.cpp` 文件按 C 编译（工具链没有 arm-none-eabi-g++）

## 正确性验证

方法：`host/nes_host` 和板子用同一份核心、同一个按键脚本运行，逐帧比对画面 CRC32。

| ROM | Mapper | ROM 位置 | 检查帧 | 结果 |
|---|---|---|---|---|
| Super Mario Bros. | 0 | RAM | 100/300/450/600 | 4/4 一致 |
| Contra (U) | 2（CHR-RAM） | Flash | 200/600/1000/1500 | 4/4 一致 |
| 2048 | 0 | RAM | 100/300/450/600 | 4/4 一致 |

打开声音后重测仍然一致。

DMA 推屏后又测了一遍：像素不再清背景标记位，所以和 `host/nes_host --raw 1` 比对，SMB 和 Contra 各 4 帧全部一致；另外在检查帧从 LCD 显存读回第 120 行逐像素比对，4 次都是 0 个不一致；DMA 传输错误计数为 0。

## 性能

每帧耗时分解（SMB 第 300~900 帧，全画质，优化前）：

| 项目 | 每帧 |
|---|---|
| 6502 CPU 模拟 | 5.4 ms |
| PPU 扫描线渲染 | ~10.9 ms |
| 推屏（FSMC） | 4.6 ms |
| 合计 | ~20.5 ms（48fps） |

优化记录：

| 尝试 | 结果 |
|---|---|
| 跳过空的 MapperPPU 回调 | 基本没变化 |
| 像素直接用 RGB565 | 推屏 4.6 → 3.5ms，采用 |
| `-O3` | 快 1.7%，Flash 多 21K，未采用 |
| `-Os` | 慢 21% |
| FSMC 写时序 A2D3 → A1D2 | 只快 0.02ms，未采用 |
| 热点代码放 SRAM 执行 | 慢 40%，撤回 |
| SRAM 重映射到 0 地址执行 | 慢 8%，撤回 |
| 隔行渲染 | 渲染+推屏减半，作为降级手段 |
| 绝对时间表限速 + 自动降级 | 采用 |
| 精灵合成优化 | SMB 20.5 → 14.6ms，Contra → 16.4ms，采用 |
| 加声音 | 每帧多约 1.1ms |
| **推屏改 DMA**（内存到内存，两块行缓冲轮换免拷贝，不清背景标记位） | **每帧省约 2.7ms**，CPU 等 DMA 的时间每帧只有约 0.2ms。收益比预估的 1~2ms 大，总线争用不明显。采用，默认开启 |

全画质时每帧实际计算耗时：

| ROM | 无声音 | 有声音 | 有声音 + DMA 推屏（当前默认） |
|---|---|---|---|
| Super Mario Bros. | 14.5 ms | 15.6 ms | **12.9 ms**，自动模式一直全画质 |
| Contra | 16.4 ms | 16.8 ms | **14.0 ms**，自动模式一直全画质（之前基本停在隔行） |

一帧预算 16.64ms（NTSC 60.0988Hz）。

## 已知问题

- **HAL_SD_Init 偶发超时**（错误码 0x80000000，约 30~40%）：已加重试，第 2 次都成功。怀疑是 HAL 初始化末尾轮询读 SD Status / SCR 的时序竞争
- **隔行渲染的副作用**（DMA 推屏后正常游戏已经很少降级到隔行）：运动和精灵闪烁时有横向细缝；Mapper 9/10（MMC2）依赖 MapperPPU 回调切 CHR，隔行时画面可能出错
- **不支持的 Mapper**：5、6、19、85、188、235
- **声音**：只验证了 DMA 在转、波形有起伏、缓冲不欠载，没有实际听过；混音是 5 路直接相加，无滤波和音量控制
- **存档**：最多每 30 秒写一次；没有用真实的带电池游戏测过
- **中文文件名**：字库只有 ASCII
- `/NES/SAVE/2048.sav` 是测试遗留文件，可以删除

## 踩过的坑

- **中断函数放进静态库不会被链接**：启动文件里的弱定义先满足了引用，SysTick 进 Default_Handler 死循环，表现是上电卡死、没有日志。`stm32f4xx_it.c` 必须直接编进可执行文件
- **HAL 的 `RCC_SYSCLK_DIVx` 和 `RCC_HCLK_DIVx` 不能混用**：APB 分频填错不会报错，但会把 AHB 悄悄分频，CPU 只剩一半速度
- **`DMA_SxCR_DIR` 在这版 CMSIS 里是 2 位掩码（0xC0）**：直接用会写成非法值，流使能不上；存储器 → 外设用 `DMA_SxCR_DIR_0`，内存 → 内存用 `DMA_SxCR_DIR_1`（且必须开 FIFO 模式，PAR 是源、M0AR 是目标）
- **DMA 推屏时 CPU 也要写屏**（发窗口命令、画 fps 文字、进菜单）之前必须先等 DMA 传完，否则命令和像素会在总线上交错
- **链接脚本 `*(EXCLUDE_FILE(...) .text .text*)`** 只排除紧跟的第一个段名；要写成 `EXCLUDE_FILE(...) *(.text .text*)`
- **BOOT0 = 1 时程序不运行**：烧录和校验都成功，但芯片跑的是 ST bootloader
- **背光极性**：PB1 高电平点亮，不是低电平
- **MADCTL = 0x28 是镜像的**，这块屏正确横屏是 0xA8
- **st-flash read 读内存会短暂暂停 CPU**：测性能时不要边跑边轮询
